# 视频笔记性能与并发验收（2026-09-07）

## 改动与不变项

- 源码 CLI：单视频模型并发由 2 提升至 4；同一 Runtime 数据目录下的 CLI / Engine 进程共享 8 个 OS 锁保护的模型调用槽。等待可取消、有超时，进程退出释放锁。不是每视频各自拥有 8 路，也不等同于云端账户额度。
- Engine：原先最大容量为 2、默认 worker 数实际为 1；现默认同时执行 4 个任务，额外后台任务持久化排队。前台 VideoService 也可申请其余空闲任务槽。批量提交使用 `--detach`；前台 `--wait` 在全部任务槽占用时仍返回 `resource_busy`，不会自动转为后台任务。
- 每个视频运行时至多保留 4 条 app-server 连接。初始化一次，每次调用新建独立 ephemeral thread，完成后 unsubscribe；旧会话通知按 threadId 隔离，RPC 请求 ID 不复用。异常/取消/超时销毁对应连接，不影响其他连接。Windows 复用已有 Job Object 进程树隔离，父进程退出时清理子进程。
- 每章生成并通过局部确定性检查后立即独立复核。全篇来源覆盖、顺序、数字、安全检查仍在发布前执行；修正后的章节不能复用修正前的复核。保留独立复核和有界修复，不合格不发布。
- 未改模型（`gpt-5.6-terra`）、推理强度、提示词、图片证据、ASR 配置、修复预算或质量阈值。没有引入跨任务内容缓存。

连接生命周期依据 [OpenAI Docs：app-server](https://learn.chatgpt.com/docs/app-server#lifecycle-overview)。源码涉及 `codex_app_server_client.py`、`model_slots.py`、`faithful_edition_compiler.py`、`runtime.py`、`video_service.py`、`resource_lease.py` 与 `job_dispatcher.py`。
